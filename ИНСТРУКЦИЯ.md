# WSL-режим в DeepSeek Harness — установка

Инструкция для установки двух плагинов, которые дают DeepSeek Harness работать в WSL на Windows.

## Что это даёт

| Плагин | Что делает |
|---|---|
| **dsh-wsl** | Выполнение команд в WSL: инструмент `wsl`, пресет «极简模式 (WSL)» с постоянным терминалом, карточка WSL в настройках плагинов |
| **dsh-wsl-mode** | Переключатель `/wsl on` / `/wsl off` для сессии. По умолчанию **включён**: агент сам предпочитает WSL, а не Windows-шелл |

Вместе они дают то поведение: вы просите «поставь ripgrep и найди TODO» — агент делает это в Ubuntu, а файлы проекта остаются на диске `C:` и видны обоим мирам.

## Что нужно

- Windows 10 или 11.
- WSL2 с хотя бы одним дистрибутивом. Проверить: `wsl -l -v` (должен быть, например, `Ubuntu`, `VERSION 2`). Если пусто — `wsl --install` и перезагрузка.
- Установленный DeepSeek Harness (десктопное приложение).
- ~130 МБ на диске, администратор не нужен.

## Установка: вариант 1 — скрипт (рекомендую)

1. Распакуйте архив в папку **без пробелов и кириллицы**, например `C:\dsh-wsl-setup`.
2. Полностью закройте DeepSeek Harness.
3. Откройте PowerShell и выполните:

   ```powershell
   cd C:\dsh-wsl-setup
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```

4. Дождитесь строки `Готово`. Скрипт сам:
   - поставит оба пакета в профиль;
   - подготовит бинарники `node-pty`;
   - включит `dsh-wsl-mode` в список бандлов;
   - добавит строку `dsh-wsl` в `cordis.patch.yml`.
5. Запустите DeepSeek Harness.

Если профиль называется не `desktop`, укажите его: `-Profile web` (имя — это папка в `%USERPROFILE%\.dsh\profiles`).

## Установка: вариант 2 — вручную

Если скрипт не сработал. Все команды — в PowerShell.

1. Закройте DeepSeek Harness. Скопируйте папку архива, например, в `C:\dsh-wsl-setup`.

2. Поставьте пакеты:

   ```powershell
   $cli = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
   & $cli plugin --profile desktop add "file:C:/dsh-wsl-setup/dsh-wsl"
   & $cli plugin --profile desktop add "file:C:/dsh-wsl-setup/dsh-wsl-mode"
   ```

   > Код возврата `1` и сообщение про `Ignored build scripts: node-pty` — **это нормально**. Пакеты при этом устанавливаются. Проверка: в `%USERPROFILE%\.dsh\profiles\desktop\package.json` появились обе зависимости.

3. Подготовьте `node-pty` (нужен для постоянного терминала):

   ```powershell
   cd "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\node-pty"
   node scripts\prebuild.js
   ```

4. Откройте `%USERPROFILE%\.dsh\profiles\desktop\package.json` и добавьте `"dsh-wsl-mode"` в конец списка `dsh.profile.bundles`:

   ```json
   "bundles": [
     "@deepseek-ai/dsh-base",
     "@deepseek-ai/dsh-web-app",
     "@deepseek-ai/dsh-experimental-voice-input-bundle",
     "@deepseek-ai/dsh-experimental-plugin-market-bundle",
     "dsh-wsl-mode"
   ]
   ```

5. В `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` добавьте в конец:

   ```yaml
   - insert:
       - id: dsh-wsl
         name: 'dsh-wsl'
   ```

6. Запустите DeepSeek Harness.

## Проверка

1. Создайте новую сессию и наберите `/wsl` — должно ответить `WSL mode is ON for this session…`.
2. Попросите агента: «выполни `uname -a` и `pwd`» — он должен выполнить это в WSL.
3. Настройки → Плагины: там появляется карточка **WSL** со списком дистрибутивов и кнопкой прогрева.

## Как пользоваться

- **`/wsl`** — показать состояние; **`/wsl on`** / **`/wsl off`** — включить или выключить для текущей сессии. На другие сессии не влияет.
- **Пути.** Файловые инструменты агента работают с Windows-путями (`C:\project\file`), команды в WSL — с их отражением (`/mnt/c/project/file`). Это один и тот же файл.
- **Дистрибутив.** Настройки → Плагины → карточка WSL: выбор применяется сразу и запоминается.
- **Постоянный терминал.** Пресет «极简模式 (WSL)» при создании сессии: там bash выполняет команды в WSL и сохраняет состояние между вызовами (`cd`, переменные, `Ctrl-C`). В обычных сессиях каждая команда — отдельный шелл.

## Важно про безопасность

Команды внутри WSL **не ограничены песочницей Windows**: виртуальная машина видит все файлы Windows через `/mnt/*`. Поэтому инструмент `wsl` работает только когда сессия в режиме полного доступа (完全访问). В ограниченном режиме он откажется с пояснением — это сделано намеренно, чтобы не создавать иллюзию изоляции.

## Ограничения

- `stdin` в команды не передаётся — используйте heredoc внутри команды.
- `/mnt/*` медленнее родной файловой системы Linux: тяжёлые сборки лучше вести в домашней папке WSL, но тогда файловые инструменты её не видят.
- Файлы в `/home/...` недоступны файловым инструментам агента — только через команды.
- Если `node-pty` не собрался, постоянный терминал недоступен; остальное (обычные команды в WSL) работает.

## Удаление

1. Уберите `dsh-wsl` и `dsh-wsl-mode` из `dependencies` и `dsh.profile.bundles` в `package.json` профиля.
2. Удалите добавленную строку `dsh-wsl` из `cordis.patch.yml`.
3. Удалите папки `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-wsl*` и `%USERPROFILE%\.dsh\.agent-presets\minimal-wsl`.
4. Перезапустите приложение.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `/wsl` не распознаётся | Не перезапустили приложение, или `dsh-wsl-mode` не попал в `dsh.profile.bundles` |
| Инструмента `wsl` нет у агента | `dsh-wsl` не установлен или строка `dsh-wsl` не добавлена в `cordis.patch.yml` |
| «setting is incompatible» при установке | В архиве уже исправленная версия под 0.2.2; проверьте, что ставите именно папку из архива |
| Команда отказывает с текстом про sandbox | Переключите сессию в режим полного доступа (完全访问) |
| Постоянный терминал не открывается | Не выполнен шаг с `node-pty` (`node scripts\prebuild.js`) |
| `wsl.exe` не найден | WSL не установлен: `wsl --install` |
| Ничего не помогло | Логи установки: `%USERPROFILE%\.dsh\profiles\desktop\.plugin-manager\logs\` |
