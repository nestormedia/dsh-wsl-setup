# dsh-wsl

WSL-режим для DeepSeek Harness на Windows: команды выполняются в Ubuntu, файлы остаются общими с Windows.

Один плагин, одна установка — всё сразу. Это же репозиторий служит и бандлом плагина, и установщиком.

## Что умеет

| Возможность | Как выглядит |
|---|---|
| Команды в WSL | инструмент `wsl` у агента; каждая команда — отдельный шелл |
| Постоянный терминал | пресет «极简模式 (WSL)» при создании сессии: состояние, `Ctrl-C`, интерактивные программы |
| Переключатель режима | `/wsl on`, `/wsl off`, `/wsl` — для текущей сессии, по умолчанию включён |
| Выбор дистрибутива | карточка **WSL** в Настройки → Плагины: список дистрибутивов, прогрев, статус пресета |

Файлы проекта остаются на диске `C:` и видны обоим мирам: агент правит их как `C:\project\file`, а команды выполняет по пути `/mnt/c/project/file`.

## Что нужно

- Windows 10 или 11.
- WSL2 хотя бы с одним дистрибутивом. Проверить в PowerShell: `wsl -l -v` — должно быть что-то вроде `Ubuntu` с `VERSION 2`. Если пусто — выполнить `wsl --install` и перезагрузиться.
- Установленный DeepSeek Harness (десктопное приложение) **0.2.2-rc.1**: плагин портирован под этот рантайм.
- ~130 МБ на диске, администратор не нужен.

## Установка из интерфейса

Самый короткий путь, без git и без скриптов.

1. Откройте **Plugins** → кнопка добавления плагина (**Add plugin**).
2. Вставьте адрес репозитория:

   ```
   https://gitea.xn--txe.net/besi/dsh-wsl-setup.git
   ```

3. Подтвердите установку и перезапустите DeepSeek Harness.

Менеджер скачает пакет по git, поставит зависимости и добавит строку плагина в профиль сам.

> Постоянный терминал требует `node-pty`; он объявлен **необязательной** зависимостью, поэтому установка проходит при любом реестре. Если пакет не скачался (например, ваш реестр его не содержит), обычные команды в WSL работают, а терминал — нет; подготовить его можно, запустив `setup.ps1` из архива (см. ниже).

## Установка на Windows (без git, из архива)

Так ставит обычный пользователь: git, администратор и навыки разработчика не нужны.

### Шаг 1. Скачать архив

Откройте в браузере:

```
https://gitea.xn--txe.net/besi/dsh-wsl-setup/archive/main.zip
```

Сохраните файл, например, в `Загрузки`. Если архив передали вам файлом — шаг пропускается.

### Шаг 2. Разблокировать и распаковать

Windows помечает скачанные архивы как небезопасные, из-за этого скрипт установки может не запуститься.

1. Правый клик по архиву → **Свойства** → внизу галочка **Разблокировать** → ОК.
2. Распакуйте архив в `C:\dsh-wsl-setup` так, чтобы файл `setup.ps1` лежал прямо в этой папке.

   Внутри архива одна папка (`dsh-wsl-setup-main`), её содержимое и нужно положить в `C:\dsh-wsl-setup`.

Проверка: в папке должны лежать `setup.ps1`, `README.md`, `package.json`.

### Шаг 3. Закрыть DeepSeek Harness

Полностью: не только окно, но и значок в трее (правый клик → Выход).

### Шаг 4. Запустить установку

Откройте PowerShell (Пуск → наберите `PowerShell` → Enter) и выполните:

```powershell
cd C:\dsh-wsl-setup
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

Скрипт сам поставит плагин в профиль, подготовит компонент терминала и пропишет его в конфигурацию. В конце появится слово `Готово`.

### Шаг 5. Проверить

Запустите DeepSeek Harness, создайте новую сессию и наберите:

```
/wsl
```

Должно ответить `WSL mode is ON for this session…`. Попросите агента: «выполни `uname -a` и `pwd`» — он выполнит это в Ubuntu.

Если профиль называется не `desktop`, укажите его при установке: `-Profile web` (имя — это папка в `%USERPROFILE%\.dsh\profiles`).

4. Запустите DeepSeek Harness и в новой сессии наберите `/wsl`.

## Как пользоваться

- **`/wsl`** — показать состояние; **`/wsl on`** / **`/wsl off`** — включить или выключить режим для текущей сессии. На другие сессии не влияет.
- **Пути.** Файловые инструменты агента работают с Windows-путями (`C:\project\file`), команды в WSL — с их отражением (`/mnt/c/project/file`). Это один и тот же файл.
- **Дистрибутив.** Настройки → Плагины → карточка WSL: выбор применяется сразу и запоминается.
- **Постоянный терминал.** Пресет «极简模式 (WSL)» при создании сессии: bash сохраняет состояние между вызовами. В обычных сессиях каждая команда — отдельный шелл.

## Важно про безопасность

Команды внутри WSL **не ограничены песочницей Windows**: виртуальная машина видит все файлы Windows через `/mnt/*`. Поэтому инструмент `wsl` работает только когда сессия в режиме полного доступа (完全访问). В ограниченном режиме он откажется с пояснением — так сделано намеренно, чтобы не создавать иллюзию изоляции.

## Ограничения

- Потоковый ввод в команду не поддерживается — данные передаются через heredoc внутри команды.
- `/mnt/*` медленнее родной файловой системы Linux: тяжёлые сборки лучше вести в домашней папке WSL, но тогда файловые инструменты её не видят.
- Файлы в `/home/...` недоступны файловым инструментам агента — только через команды.
- Если `node-pty` не установился, постоянный терминал недоступен; обычные команды в WSL при этом работают.

## Состав

Пакет плагина лежит в корне репозитория:

| Путь | Что это |
|---|---|
| `package.json` | манифест пакета, `dsh.bundle.patch`, локали и иконка |
| `cordis.patch.yml` | бандл-патч: вставляет строку плагина в профиль |
| `lib/` | хост-половина, режим `/wsl`, PTY-бэкенд, клиентская карточка |
| `agent-presets/` | пресет «极简模式 (WSL)» |
| `test/` | юнит-тесты |
| `setup.ps1` | установщик для машины без git |
| `index.json` | индекс для Discover |
| `UPSTREAM.md` | README оригинального плагина (MIT, penglai-doll) |

## Как это устроено

- `lib/index.js` — хост-половина: установка пресета, прогрев дистрибутива, инструмент `wsl`, роуты `/wsl-manager/*`.
- `lib/mode.js` — режим сессии: команда `/wsl` и секция системного промпта, привязанная к скоупу конкретного агента. Текст секции — провайдер, поэтому переключение действует со следующего шага и не требует перезапуска.
- `lib/backend.js` — постоянный PTY: `node-pty` → ConPTY → `wsl.exe` → bash.
- `lib/client.js` — карточка WSL в настройках плагинов.

Состояние: выбор дистрибутива в `%DSH_HOME%\dsh-wsl.json`, переключатель режима — в `%DSH_HOME%\dsh-wsl-session.json` (только отклонения от «включено»).

## Совместимость

Порт [penglai-doll/dsh-wsl](https://github.com/penglai-doll/dsh-wsl) (MIT) с 0.1.0-rc.6 на 0.2.2-rc.1: заменён удалённый `effectiveSandboxMode`, namespace-API настроек заменён файловым хранилищем, обновлены peer-зависимости. Режим `/wsl` добавлен сверху и живёт в том же пакете.

## Тесты

```powershell
node --test test/mode.test.mjs     # 10 юнит-тестов режима, без WSL и без зависимостей
```

Если в WSL `node` не виден из неинтерактивной оболочки (стоит через fnm и
инициализируется в `~/.bashrc`), запускайте его по пути из alias:

```bash
cd /path/to/dsh-wsl-setup
~/.local/share/fnm/aliases/default/bin/node --test test/mode.test.mjs
```

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| PowerShell пишет, что скрипт «не может быть загружен» | Не выполнен Шаг 2 (Разблокировать). Либо в папке: `Get-ChildItem -Recurse \| Unblock-File` |
| «Выполнение сценариев отключено в этой системе» | Запускайте именно так: `powershell -ExecutionPolicy Bypass -File .\setup.ps1` |
| `cd C:\dsh-wsl-setup` — папка не найдена | Архив распакован в другое место; проверьте путь |
| Ошибка `Ignored build scripts: node-pty` при установке | Это нормально, установка продолжается; скрипт это учитывает |
| `/wsl` не распознаётся | Приложение не перезапускали после установки |
| Инструмента `wsl` нет у агента | Плагин не установился: смотрите логи в `%USERPROFILE%\.dsh\profiles\desktop\.plugin-manager\logs\` |
| Команда отказывает с текстом про sandbox | Переключите сессию в режим полного доступа (完全访问) |
| Постоянный терминал не открывается | Не установился `node-pty`; обычные команды при этом работают |
| `wsl.exe` не найден | WSL не установлен: `wsl --install` и перезагрузка |
| «incompatible» при установке | Плагин рассчитан на DeepSeek Harness 0.2.2-rc.1 |

## Удаление

1. Закройте DeepSeek Harness.
2. Удалите пакет из профиля: **Plugins → Installed → WSL → удалить**, либо вручную — папку `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-wsl`, строку `"dsh-wsl"` из `dependencies` в `package.json` профиля и блок `- insert: - id: dsh-wsl` из `cordis.patch.yml`.
3. Удалите папку `%USERPROFILE%\.dsh\.agent-presets\minimal-wsl`.
4. Запустите приложение.
