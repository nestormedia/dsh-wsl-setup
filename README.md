# dsh-wsl

WSL-режим для DeepSeek Harness на Windows: команды выполняются в Ubuntu, файлы остаются общими с Windows.

Репозиторий одновременно служит бандлом плагина: ставится прямо из интерфейса DeepSeek Harness, без git и без скриптов.

## Что умеет

| Возможность | Как выглядит |
|---|---|
| Команды в WSL | инструмент `wsl` у агента; каждая команда — отдельный шелл |
| Постоянный терминал | пресет «极简模式 (WSL)» при создании сессии: состояние, `Ctrl-C`, интерактивные программы |
| Переключатель режима | `/wsl on`, `/wsl off`, `/wsl` — для текущей сессии, по умолчанию включён |
| Выбор дистрибутива | карточка **WSL** в Настройки → Плагины: список дистрибутивов, прогрев, статус пресета |

Файлы проекта остаются на диске `C:` и видны обоим мирам: агент правит их как `C:\project\file`, а команды выполняет по пути `/mnt/c/project/file`.

## Что нужно

- Windows 10 или 11.
- WSL2 хотя бы с одним дистрибутивом. Проверить в PowerShell: `wsl -l -v` — должно быть что-то вроде `Ubuntu` с `VERSION 2`. Если пусто — выполнить `wsl --install` и перезагрузиться.
- DeepSeek Harness **0.2.2-rc.1**: плагин портирован под этот рантайм.
- ~130 МБ на диске, администратор не нужен.

## Установка

1. Откройте **Plugins** и нажмите добавление плагина (**Add plugin**).
2. Вставьте адрес репозитория — **с `.git` на конце**:

   ```
   https://gitea.xn--txe.net/besi/dsh-wsl-setup.git
   ```

3. Нажмите **Install** и дождитесь завершения.

   > Без `.git` pnpm принимает адрес за tarball и падает с `ERR_PNPM_TARBALL_EXTRACT` — это самая частая ошибка.

   > Если в диалоге выбран **Registry: Custom address** и вашего реестра нет в нём нужных пакетов — установка всё равно пройдёт: `node-pty` объявлен необязательной зависимостью.

4. Перезапустите DeepSeek Harness.

Строку плагина добавлять вручную не нужно: пакет объявляет бандл-патч, и запись появляется в профиле сама.

## Установка из индекса (Discover)

Если удобнее ставить из каталога, а не по адресу: откройте **Plugins → Discover**, нажмите **Add index source** и укажите

```
https://gitea.xn--txe.net/besi/dsh-wsl-setup/raw/branch/main/index.json
```

В списке появится карточка **WSL** с иконкой и описанием, у неё — кнопка **Install**. Дальше то же самое: установка и перезапуск.

## Проверка

1. Создайте новую сессию и наберите `/wsl` — должно ответить `WSL mode is ON for this session…`.
2. Попросите агента: «выполни `uname -a` и `pwd`» — он выполнит это в Ubuntu.
3. Настройки → Плагины: карточка **WSL** со списком дистрибутивов и кнопкой прогрева.

## Постоянный терминал

Постоянному терминалу нужен `node-pty`. Он объявлен необязательной зависимостью: если реестр его не отдал, установка не падает, обычные команды в WSL работают, а терминал недоступен.

Чтобы подготовить его на машине, где `node-pty` не встал, запустите установщик из архива:

1. Скачайте `https://gitea.xn--txe.net/besi/dsh-wsl-setup/archive/main.zip` и распакуйте в `C:\dsh-wsl-setup`.
2. Правый клик по архиву → **Свойства** → **Разблокировать**.
3. Закройте DeepSeek Harness и выполните в PowerShell:

   ```powershell
   cd C:\dsh-wsl-setup
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```

Скрипт поставит пакет заново и разложит бинарники `node-pty`.

## Как пользоваться

- **`/wsl`** — показать состояние; **`/wsl on`** / **`/wsl off`** — включить или выключить режим для текущей сессии. На другие сессии не влияет.
- **Пути.** Файловые инструменты агента работают с Windows-путями (`C:\project\file`), команды в WSL — с их отражением (`/mnt/c/project/file`). Это один и тот же файл.
- **Дистрибутив.** Настройки → Плагины → карточка WSL: выбор применяется сразу и запоминается.
- **Постоянный терминал.** Пресет «极简模式 (WSL)» при создании сессии: bash сохраняет состояние между вызовами. В обычных сессиях каждая команда — отдельный шелл.

## Важно про безопасность

Команды внутри WSL **не ограничены песочницей Windows**: виртуальная машина видит все файлы Windows через `/mnt/*`. Поэтому инструмент `wsl` работает только когда сессия в режиме полного доступа (完全访问). В ограниченном режиме он откажется с пояснением — так сделано намеренно, чтобы не создавать иллюзию изоляции.

## Ограничения

- Потоковый ввод в команду не поддерживается — данные передаются через heredoc внутри команды.
- `/mnt/*` медленнее родной файловой системы Linux: тяжёлые сборки лучше вести в домашней папке WSL, но тогда файловые инструменты её не видят.
- Файлы в `/home/...` недоступны файловым инструментам агента — только через команды.
- Если `node-pty` не установился, постоянный терминал недоступен; обычные команды в WSL при этом работают.

## Обновление и удаление

**Обновление.** Поставьте плагин тем же адресом ещё раз — новая версия встанет поверх. В индексе для этого есть карточка с версиями и кнопкой **Install**.

**Удаление:**

1. Закройте DeepSeek Harness.
2. Удалите плагин: **Plugins → Installed → WSL → удалить**, либо вручную — папку `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-wsl`, строку `"dsh-wsl"` из `dependencies` и `dsh.profile.bundles` в `package.json` профиля.
3. Удалите папку `%USERPROFILE%\.dsh\.agent-presets\minimal-wsl`.
4. Запустите приложение.

## Состав

Пакет плагина лежит в корне репозитория:

| Путь | Что это |
|---|---|
| `package.json` | манифест пакета, `dsh.bundle.patch`, локали и иконка |
| `cordis.patch.yml` | бандл-патч: вставляет строку плагина в профиль |
| `lib/` | хост-половина, режим `/wsl`, PTY-бэкенд, клиентская карточка |
| `agent-presets/` | пресет «极简模式 (WSL)» |
| `test/` | юнит-тесты |
| `index.json` | индекс для Discover |
| `setup.ps1` | установщик для машин, где нужен `node-pty` |
| `UPSTREAM.md` | README оригинального плагина (MIT, penglai-doll) |

## Как это устроено

- `lib/index.js` — хост-половина: установка пресета, прогрев дистрибутива, инструмент `wsl`, роуты `/wsl-manager/*`.
- `lib/mode.js` — режим сессии: команда `/wsl` и секция системного промпта, привязанная к скоупу конкретного агента. Текст секции — провайдер, поэтому переключение действует со следующего шага и не требует перезапуска.
- `lib/backend.js` — постоянный PTY: `node-pty` → ConPTY → `wsl.exe` → bash.
- `lib/client.js` — карточка WSL в настройках плагинов.

Состояние: выбор дистрибутива в `%DSH_HOME%\dsh-wsl.json`, переключатель режима — в `%DSH_HOME%\dsh-wsl-session.json` (только отклонения от «включено»).

## Тесты

```powershell
node --test test/mode.test.mjs     # 10 юнит-тестов режима, без WSL и без зависимостей
```

Если в WSL `node` не виден из неинтерактивной оболочки (стоит через fnm и
инициализируется в `~/.bashrc`), запускайте его по пути из alias:

```bash
cd /path/to/dsh-wsl-setup
~/.local/share/fnm/aliases/default/bin/node --test test/mode.test.mjs
```

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `ERR_PNPM_TARBALL_EXTRACT` при установке | Адрес вставлен без `.git` — добавьте `.git` |
| `ERR_PNPM_FETCH_403` на `node-pty` | Установка идемпотентна: повторите с обычным реестром, либо проигнорируйте — с 0.6.0 `node-pty` необязателен |
| «This is not a package name or address that can be installed» | Это поле для плагина, а не для ссылки на индекс; индекс добавляется в **Discover → Add index source** |
| `/wsl` не распознаётся | Приложение не перезапускали после установки |
| Инструмента `wsl` нет у агента | Плагин не активировался: смотрите логи в `%USERPROFILE%\.dsh\profiles\desktop\.plugin-manager\logs\` |
| Команда отказывает с текстом про sandbox | Переключите сессию в режим полного доступа (完全访问) |
| Постоянный терминал не открывается | Не установился `node-pty` — см. раздел «Постоянный терминал» |
| `wsl.exe` не найден | WSL не установлен: `wsl --install` и перезагрузка |
