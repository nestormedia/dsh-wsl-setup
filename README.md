# dsh-wsl-setup

WSL-режим для DeepSeek Harness на Windows: команды выполняются в Ubuntu, файлы остаются общими с Windows.

Комплект из двух плагинов и установщика.

## Состав

| Папка / файл | Что это |
|---|---|
| `dsh-wsl/` | Плагин выполнения команд в WSL: инструмент `wsl`, пресет «极简模式 (WSL)» с постоянным PTY, карточка WSL в настройках |
| `dsh-wsl-mode/` | Переключатель режима для сессии: `/wsl on`, `/wsl off`, по умолчанию включён |
| `setup.ps1` | Автоматическая установка в профиль DSH |
| `ИНСТРУКЦИЯ.md` | Подробная инструкция: установка, проверка, ограничения, удаление |

## Быстрый старт

1. Распаковать (или склонировать) в `C:\dsh-wsl-setup` — путь без пробелов.
2. Закрыть DeepSeek Harness.
3. В PowerShell:

   ```powershell
   cd C:\dsh-wsl-setup
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```

4. Запустить DeepSeek Harness и в новой сессии набрать `/wsl`.

Подробности, ручной путь установки и таблица неполадок — в [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md).

## Требования

- Windows 10/11, WSL2 с установленным дистрибутивом (`wsl --install`).
- DeepSeek Harness **0.2.2-rc.1**: плагин портирован именно под этот рантайм.
- Для инструмента `wsl` сессия должна быть в режиме полного доступа: процессы внутри WSL не ограничены песочницей Windows.

## Совместимость

`dsh-wsl` — порт [penglai-doll/dsh-wsl](https://github.com/penglai-doll/dsh-wsl) (MIT) с 0.1.0-rc.6 на 0.2.2-rc.1: заменён удалённый `effectiveSandboxMode`, namespace-API настроек заменён файловым хранилищем, обновлены peer-зависимости.

`dsh-wsl-mode` написан с нуля: секция системного промпта регистрируется в скоупе конкретного агента, поэтому переключатель действует на одну сессию и не требует перезапуска.
